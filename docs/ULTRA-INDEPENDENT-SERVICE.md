# ULTRA 独立服务接入状态

日出海岸仍使用现有本地存档；账号注册与云存档未启用，未自动上传用户数据。PHP 服务须在独立 PHP 主机运行，GitHub Pages 只发布静态游戏。

独立服务基线已单独保留为非公开交付文件。未来若建立服务源码分支，该分支不应作为 Pages 发布源，也不应合并到 main 的静态目录。当前 main 有 `.nojekyll`，`_services/` 等下划线目录同样可能被公开；主线不存 PHP、服务环境配置、数据库、运行时二进制或凭据。

服务基线使用精确 HTTPS Origin/Host 校验，默认不信任转发头，只有明确配置的代理 IP 可以报告 TLS；跨站访问拒绝，无开放 CORS。未配置时返回 503；配置完成也仅返回真实维护状态，所有注册、登录和存档操作继续 503，不发会话 Cookie、不读取账号和存档。基线没有“开启即可上线”的环境开关。

未来安全接入宜采用同一自有游戏 HTTPS 域名反向代理 `/coast-api/` 到独立服务，并保留 Secure、HttpOnly、SameSite=Strict 的 `__Host-` Cookie、CSRF 与账号上下文隔离。当前 GitHub Pages 地址没有这个代理，不能把 PHP 文件或跨站 fetch 直接当成完成集成。独立服务部署和同源路由均待真实托管验证。

恢复包账号/分块存档核心通过本地假 KV 测试，仍不证明真实平台一致性。旧完整快照只支持 coast-plateau-final-v4 世界和 31 车型；新地图/摩托/新增字段必须建立精确契约。真实恢复的本地备份、异步资产准备及安全提交、账号生命周期、容量回收与抗滥用验收仍未完成。不得以旧 schema 丢字段、假成功响应或放宽 CORS 掩盖缺失集成。

所有历史版本、测试入口、现有存档键和备份继续保留。只有独立服务、浏览器会话、真实托管并发和当前游戏完整恢复通过验收后，才可以在功能状态中标记账号/云存档已上线。
